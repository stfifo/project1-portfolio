확인할 수 있는 결과

주소를 검색하면 도로명지번 주소 후보가 나오고, 하나를 고르면 요약 → 개별공시지가(연도별 꺾은선 차트) → 토지이용계획 → 토지대장 → 건축물대장 순서로 한 페이지에 이어서 표시됩니다. 상단 내비게이션으로 각 섹션으로 이동할 수 있고, 여러 주소를 탭으로 열어둘 수 있습니다.

만든 과정과 해결한 문제

무엇을 만들려고 했나

회사가 보유한 토지에 건물을 지으려면 용도지역, 건폐율, 용적률 같은 규제와 토지 소유 구분, 기존 건축물 현황, 공시지가를 각각 다른 사이트에서 확인해야 했습니다. 이를 "땅을 살 수 있는가 → 사도 건물을 지을 수 있는가"를 한 번에 판단할 수 있도록 주소 하나로 4종 정보를 모아 보여주는 서비스를 목표로 했습니다. 처음 화면 설계는 탭을 눌러 내용을 전환하는 방식이었지만, 시안을 직접 보니 탭 전환이 번거로워 보고서처럼 전부 이어 보여주고 상단 버튼은 앵커 내비게이션으로 쓰는 방식으로 바꿨습니다.

어디에서 막혔고, 어떻게 풀었나

1. VWorld 인증 오류
호출 테스트에서 VWorld API가 계속 INCORRECT_KEY로 실패했습니다. 같은 VWorld인 Geocoder는 정상이라 키 자체보다 정책 문제로 보고 확인한 결과, 요청의 domain 파라미터와 Referer 헤더가 키 발급 시 등록한 도메인과 정확히 일치해야 했습니다. 두 값을 맞추니 3종 모두 정상 응답했습니다.

2. 배포 서버에서만 되는 차단
로컬에서는 성공했지만 배포 서버에서는 RemoteDisconnected/502가 발생했습니다. 서버의 아웃바운드 IP가 vworld.kr에서 차단되는 것으로 판단했고, VWorld 자주 묻는 질문 게시판과 다른 개발자의 사례를 참고해 백엔드를 거치지 않고 브라우저가 VWorld를 JSONP로 직접 호출하도록 바꿨습니다. 요청의 출처는 코드가 저장된 곳이 아니라 요청을 실제로 보내는 기기의 IP라서, 사용자의 국내 통신사 IP로 나가기 때문에 우회가 가능합니다. 저장할 데이터가 없는 조회 서비스라 이 방식을 택했고, 건축물대장과 주소 검색처럼 차단되지 않는 API는 기존대로 백엔드를 거칩니다.

3. 일부 주소만 "정보 없음"
배포 후 다른 주소를 검색하면 totalCount가 0으로 나왔습니다. 특정 PNU로 직접 호출하면 정상이어서 주소 검색 결과를 조합해 만든 PNU를 의심했고, 구성 요소를 하나씩 비교해 원인을 찾았습니다. 필지구분 자리를 건축물대장 코드 체계(0=대지, 1=산)로 넣고 있었는데, PNU에서는 1=일반, 2=산이었습니다. 두 코드를 따로 변환하도록 수정해 해결했습니다.

4. 정적인 로딩 화면과 불안정한 호출
단순히 "조회 중" 글자만 보이고 언제까지 기다려야 하는지 알 수 없다는 지적을 받았습니다. 또 호출이 되다 안 되다 했는데, 화면의 타임아웃(5초)이 실제 네트워크 타임아웃(8초)보다 짧았고, 실패 응답이 순수 JSON인데 Content-Type은 application/javascript로 내려와 Chrome의 ORB가 스크립트를 막아 5개 호출 중 하나만 걸려도 곧바로 오류 화면이 뜨는 문제가 겹쳐 있었습니다. 화면 타임아웃을 네트워크보다 길게 늘리고, 실패하면 여러 번 자동 재시도한 뒤에도 안 되면 재시도 버튼을 보여주도록 했습니다.

어떻게 확인했고, 무엇이 남았나

PNU 수정 후 같은 필지로 다시 호출해 토지임야정보 0건→1건, 토지이용계획 0건→13건, 개별공시지가 0건→40건으로 바뀐 것을 확인했습니다. 재시도 로직은 배포 서버에서 여러 주소로 반복 조회해 확인했습니다. 새로고침하면 검색 내용이 랜딩 페이지로 초기화되던 문제는 캐시가 아니라 "새로고침에도 남는 저장소" 문제임을 이해하고, 열린 탭의 주소 후보와 활성 탭 id만 localStorage에 저장했다가 다시 열 때 복원하도록 고쳤습니다. 이후 localStorage 처리와 일부 컴포넌트를 App.jsx에서 분리하는 리팩토링으로 마무리했습니다.
