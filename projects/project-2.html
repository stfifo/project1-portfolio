만든 과정과 해결한 문제

무엇을 만들려고 했나

데이터 충분성 에이전트 바탕으로 시장 상황에 대한 보고서를 만들고, 보고서의 어려운 개념을 클릭하면 해당 개념 페이지를 확인할 수 있는 주식 서비스를 만들고자 하였습니다. 보고서와 함께 주식 지표를 확인하며 관련 정보와 지표를 학습하는 것을 목표로 하였습니다.

어디에서 막혔고, 어떻게 풀었나

홈과 종목 상세가 하나의 클라이언트와 호출 제한을 공유하기 때문에 홈 수집을 먼저하고 남는 시간에 종목 상세를 처리하는 방향으로 구현했습니다. 팀원간 리뷰를 통해 지금은 괜찮지만 나중에는 여러 종목 조회가 동시에 몰릴 수 있음 + 홈 수집 주기가 촘촘해져서 종목 상세의 순위가 뒤로 밀림 등의 문제가 발생할 수 있음을 확인했습니다. OS scheduling 개념을 참고하는 방향으로 starvation 문제를 해결하되, 지금 단계에서는 특정 scheduling algorithm을 먼저 고르기보다는 상세 요청 p95 대기시간, 홈 데이터 freshness, API rate limit 발생 횟수 등의 관련 지표를 관측할 수 있는 log 를 만들어두고 이후 정책 변경의 근거로 활용하고자 하였습니다

어떻게 확인했고, 무엇이 남았나

보고서 생성시 데이터 충분성을 판단하는 에이전틱 요소를 넣어서 보고서의 품질을 보완하고자 했습니다. 처음에는 근거의 출처 명확성을 바탕으로 충분성을 평가하려고 했으나 주식이라는 도메인 특성상 근거가 더 좋은 내용임을 보장하는지에 대한 의구심이 들었습니다. 데이터 충분성은 어떻게 평가할 것인가?에 대해 어려움이 생겨서 생성된 보고서에 대해 사람이 "충분 / 정보 부족 / 근거는 있으나 인과가 약함 / 근거 충돌 / 명확한 원인을 찾기 어려움" 정도로 분류한 후 데이터 충분성 판단 지표를 다시 정하고자 합니다
